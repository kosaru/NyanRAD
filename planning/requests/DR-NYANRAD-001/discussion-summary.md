# NyanRAD 初期構想の整理

この文書は対話の記録です。要件定義成果物、承認済み仕様、実装指示の代替にはしません。

## 人間から示された意図

| 発言 | 記録する意図 |
|---|---|
| 「VisualBasicみたいな仕組み」「ブラウザ上で動くもの」 | ブラウザ上で使えるビジュアル開発環境を検討する |
| 「VB6に近いかな。Accessだと敷居が高い気がする」 | VB6に近い画面中心の操作を志向する |
| 「ポトペタで画面作れるけど生成物はソースコード」 | 部品配置で画面を作り、ソースコードを生成物とする |
| 「NyanQLフレームワーク群の体裁を保つのが大前提」 | NyanQL群に沿った生成物であることを前提とする |
| kosaru/NyanRADを作成した旨の連絡 | プロジェクト名とリポジトリをNyanRADとする |

「体裁を保つ」の具体的なフォルダ構成、設定形式、対応製品・バージョン、許容する追加依存は未決定です。

## 目的の明確化

要求者の発言：「基本的にはVB6のようにNyanQLフレームワークを使えるようにすると言うのが目的だからね。」

この目的を軸に、VB6の開発操作とNyanQL群のソース・実行方式の対応を検討する。特定の業務アプリや初心者向けへの限定を前提にしない。[対応案と生成ソース例](vb6-nyan-mapping.md)は追加調査資料であり、採用済み要件ではない。

## 背景と期待

画面から作り始められる開発環境を求めています。Access型の仕組みについては、要求者が敷居の高さを感じています。現在の具体的な開発作業、困り事の頻度、対象利用者の経験、時間や費用の目標はまだ聞き取っていません。

## 会話でAIが提案した案（未承認）

- ツールボックス、プロパティ欄、部品のダブルクリックによるイベント編集。
- HTML・CSS・ブラウザ用JavaScriptと、必要に応じたサーバー用JavaScript・SQL・api.jsonの生成。
- 生成物を開発環境から切り離して通常のNyanQL群で実行できる構成。
- 手書きコードを再生成で上書きしない仕組み。
- デザイナーが扱える記述形式を定め、対応外のコードはカスタム部分として保持する案。
- フォーム、ラベル、入力欄、ボタン、選択欄、一覧表から始める案。
- NyanPUIを画面配信、NyanQLをDB処理、必要に応じNyan8を処理・連携、NyanKITを配置の参考とする案。

これらは採用済みの設計・対象範囲ではありません。VB言語互換性、JavaScript採用、専用実行ライブラリの可否も未決定です。
