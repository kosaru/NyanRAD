## 操作ごとの確認

| 処理 | 要件資料との照合 | 残ること |
|---|---|---|
| CREATE | 新規作成と作成先保護に対応 | 「既存ファイルがない」だけでは、確認済みの「既存の空フォルダ」と新規フォルダの扱い、再確認の条件をこの行だけでは読み取れない。EMPTYDIRも併せて確認する |
| OPEN | 読込と再編集可能範囲の表示に対応 | 不足ファイル・読めない設定・非対応形式の表示は正常行では扱われていない。別処理または補足での表現を確認 |
| SAVE | 対象ごとの保存結果に対応 | 成功確認前に未保存表示を消さない点は、元資料では案であり、この行には明記がない。確定度を調べる |
| CONFLICT | 差分と再読込・明示上書き・中止に対応 | 上書きを既定選択にしないことは行に明記されていない |
| SAVEFAIL | 失敗対象・未保存内容の表示と部分保存中の実行停止に対応 | 保存失敗の全範囲と部分保存状態の解消方法は別途確認 |
| EXISTS | 既存ファイルがある作成先で生成を止める方針に対応 | 既存プロジェクトを開く導線は行に明記されていない |
| RELOAD | 差分確認、対象の未保存変更の破棄確認、無関係な編集の保持に対応 | 読込自体が失敗した場合の導線は未確認 |
| OVERWRITE | 置換対象の確認と再変更の確認に対応 | 確認から保存までの競合防止の技術成立は未実証 |
| CANCEL | 保存先・未保存編集を保持する方針に対応 | 画面への戻り先は詳細未確認 |
| RECHECK | 判断後の再変更時に差分確認へ戻る方針に対応 | 実際に再変更を検出できるかは未実証 |
| SWITCHSAVE | 保存成功後の切替という流れを表現 | 保存が完了しない場合はSWITCHFAILを参照 |
| SWITCHDISCARD | 未保存内容を破棄して切り替える選択肢に対応 | 具体的な対象表示や再読込失敗時の導線は未確認 |
| SWITCHCANCEL | 切替・再読込を中止し編集中内容を保持する方針に対応 | 保存先の変更有無を含む詳細は未確認 |
| SWITCHFAIL | 失敗を成功扱いせず、対象別結果と未保存内容を示す行がある | 下記の**要確認A** |
| EMPTYDIR | 既存の空フォルダと生成直前の再確認に対応 | 再確認できない場合や直後の変更の扱いは別途確認 |
| CREATEFAIL | 作成済み対象を示しフォルダ全体を自動削除しない方針に対応 | 元資料にある「今回作ったものと既存のものを区別」は行に明記されていない |

## 要確認A：切替前の保存が失敗した場合

[機能検討](../requirements/09-functions.md)の「今回確認された操作方針」は、保存失敗を成功と扱わない一方で、**実行・切替を続行する詳細条件は別途定める**と記載している。対象の構造化資料ではSWITCHFAILの機能名が「保存失敗で切替を止める」となっているが、同じ処理の結果と人間向け確認表には「成功扱いせず対象別結果と未保存内容を示す」とあり、切替を止めるとは明記していない。

この違いだけでは、保存失敗時に切替を必ず止めることまで既に合意されたとは判定できない。関連する後続の人間判断があるか引き続き確認し、なければ、例えば「保存に失敗したら切替は行わず、結果を示して編集画面に留まる」という扱いを人間へ確認したうえで資料を同期する。これは提案であり、今回採用した要件ではない。
