# NyanRAD：要件定義、その前に

## 今回進めること

NyanRADの目的と初期範囲を土台として、利用者が必要とする画面・機能・データを順に明らかにする。
要求者は「はいお願いします。要件定義着手してください。」と明示した。今回の着手は、詳細要件や実装、正式リリースの承認とは区別する。

## 進め方と関係者

要求者が目的、範囲、要件の意味、提供条件を判断する。AIは既存の合意を引き継いで資料を作り、提案・未決定事項を明示する。
技術調査や資料間の整合確認はAIが進め、意味や提供範囲の変更が必要な場合に判断を求める。

企画を確認する → 全体像を描く → 大まかに区分けする → 実装技術を決める → 実現したいことを整理整頓する → 利用者の行動シナリオを書く → 概念データモデルを作る → UIを考える → 機能について考える → データについて考える → 要件定義を仕上げる → 要件定義、その後に、の順で進める。

## 資料と履歴

人間向けの説明は文書・図・表で示し、内部のIDや状態管理を確認資料の中心にしない。
既存の構想資料は入力として参照し、工程ごとの検討を置き換えない。
GitHubの進捗一覧・Issueに成果物と判断を残す。正式な承認時には判断した資料の版を固定する。
