# NyanRAD 部品・イベント・配置・再編集の対応案

## 初回デザイナーの方針確認

要求者は「この範囲で進めてよいですか」への回答として「はい。この方針で進めて。」と明示した。
初回はVB6に近い固定座標中心の配置、基本部品とClick・Change等のイベント、通常JavaScriptによるイベント処理、表示・行選択までの一覧表を軸とする。
手編集したコードを保持し、対応外の表現がある場合は編集可能な範囲を制限する。

この節は同じ論点について以前「提案」「未決定」とした記述を更新する。詳細なDOMイベントの時機、イベント引数、コピー時の処理対応、Undo範囲、部品別の細目は未確定のまま残す。
一覧表のセル内編集・ソート・検索・ページ分割やDB自動更新まで採用した意味ではない。



## 提案の位置づけ

VB6風の画面操作を、通常のHTML・CSS・JavaScriptへ対応づける初回案。
既存の基本部品候補を具体化する資料であり、新しい詳細範囲の採用はまだ決定していない。
前回了承された未保存時の選択、競合の差分表示、手書き本文の保持、失敗表示の方針を前提とする。

## 初回部品と編集できる項目の案

| 部品 | 出力先の例 | 主な編集項目 | 初回イベント候補 |
|---|---|---|---|
| フォーム | HTMLの画面領域とCSS | 名前、画面タイトル、幅・高さ、背景 | Load |
| ラベル | label等 | 名前、表示文字、対応する入力、表示状態 | Click |
| 入力欄 | input type=text | 名前、値、案内文字、読取専用、無効状態 | Change、Input、Focus、Blur |
| 複数行入力 | textarea | 入力欄に準じる項目、寸法 | Change、Input、Focus、Blur |
| ボタン | button | 名前、表示文字、無効状態 | Click |
| チェック | input type=checkboxと表示ラベル | 名前、表示文字、チェック状態 | Change |
| 選択欄 | selectとoption | 名前、選択肢の値と表示、選択値 | Change |
| 一覧表 | table等 | 名前、列の名前と見出し、列順、幅 | 行選択 |

全要素に同じプロパティを無条件に付けない。表示・有効状態等の意味はHTMLの要素と対応させる。
一覧表はまず表示と行選択を候補にし、セル内編集、ソート・検索・ページ分割、DBへの自動更新は別の採用判断とする。
フォームLoadは初期表示時にイベント結線が利用可能となった段階で呼ぶ案。画像等の全リソース読込完了とは区別する。
Changeは値の確定、Inputは入力に伴う変化として区別する。具体的なDOMイベントと呼出タイミングは詳細仕様で固定する。
VB風の名称はIDE上の表示案であり、VB言語やVB6のイベント順序との互換保証ではない。

## コードを書く操作

ボタンはダブルクリックでClick、入力欄・選択欄・チェックはChange、フォームはLoadを開く案。
部品・イベント選択欄から他の対応イベントへ切り替える。
処理本文は通常のJavaScriptとして編集し、対象とイベントを結ぶ部分をIDEが管理する案。
独自のVB構文・暗黙のText等のプロパティを導入する案ではない。
一覧表の行選択で渡す情報や共通のイベント引数形式は未決定。部品の出力HTMLも例であり実装構造を確定しない。

## 配置方法の比較

| 案 | 開発者の操作 | 生成ソースと制限 |
|---|---|---|
| A：固定座標中心 | VB6のように位置と幅・高さを編集 | CSSの座標等へ対応。狭い画面への自動追従は保証範囲に入れない |
| B：自動配置中心 | 行・列や並び順、余白を編集 | Flex／Grid等の配置規則へ対応。VB6風の自由配置との操作差がある |
| C：両方を初回から扱う | 固定配置と自動配置を選ぶ | 選択肢と変換規則、再編集対象が増える |

初回の推薦はA。macOS上のローカル開発でVB6風の配置を一巡させる目的に沿う。
表示の拡大縮小やスクロールと、生成アプリのレスポンシブ対応は分けて扱う。
フォーム外へ出た部品の扱い、最小寸法、グリッドへの吸着、キーボードでの移動量は別途具体化する。

## ソースの再編集範囲の案

| 手編集の内容 | デザイナーでの扱いの案 |
|---|---|
| 手書きイベント本文・共通処理の変更 | 本文を保持する。配置変更で再生成しない |
| IDEが扱う部品の文字・属性・配置値の変更 | 対応する表現なら再読込してプロパティへ反映する |
| 対応部品の追加・削除・名前変更 | 識別・対応が確認できる場合のみ取り込む。結線や参照の不足は示す |
| 独自CSS・独自HTMLの追加 | 対応外の部分を保持する。編集できる範囲を示す |
| 複雑なCSSがIDEの配置規則と競合 | 見かけだけを確定値にせず、配置編集を制限して理由を示す案 |
| 実行中にJavaScriptで生成・移動するDOM | 実行結果からデザインを逆生成する保証はしない |
| 手書きでイベント結線を変更 | 元のコードを保持し、IDE管理の結線と識別できない場合は警告・編集制限の候補 |
| 解析できない・構文が壊れたソース | 元ソースを保持して問題を表示。空のフォーム等で置換しない |

「対応外がある」ことと「プロジェクト全体を編集不能にする」ことは同じではない。どの部品・属性・ファイルを制限するかを示す案。
ただし、曖昧なコードを推測で書換えないために必要な範囲は編集を止める。
正本は通常ソースとし、任意ソースの完全逆変換や実行時DOMの完全取込を初回の保証に含めない提案。

## コピー・名前変更・削除・Undoの案

コピーは新しい部品名を用意し、元の手書き本文を自動複製しない方針を確認済み。処理の存在を示し、結線の詳細や処理共有操作は別途検討する。
名前変更はIDE管理の対象と結線への影響を示す。手書きJavaScript本文の任意参照を無条件の文字列置換で直さない案。
削除後も手書き処理本文を残すことは人間確認済み。消した部品を参照するコードの扱いは警告と手編集を基本候補とする。
Undo／Redoは配置・サイズ・プロパティ・追加・削除・整列・名称変更を対象とする方針を確認済み。コード履歴とは分け、同一セッションの保存後は保持し、再読込・切替で区切る。保持上限は未決定。

## 次に判断する範囲

初回は「固定座標中心」「上表の基本部品・イベント」「通常JavaScript」「対応範囲を明示した往復編集」を採用する案を推薦する。
一覧表の初回範囲や、複雑なソースでは編集を制限する扱いも含めて要求者へ確認する。
この方向が決まってから、イベント引数、コピー・Undo、配置寸法等の詳細案を揃える。
