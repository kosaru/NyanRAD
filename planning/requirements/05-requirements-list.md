# NyanRAD 実現したいこと・要求一覧（初稿）

## この一覧の読み方

企画、全体像、大まかな区分、技術比較を材料に、重複する要望をまとめた。
「確認済み」は会話で目的・前提・方向が確認されたことを表す。「初回候補」は初期範囲の検討の軸として了承された内容で、詳細要件・受入条件は未確定。
優先順位の数値や実装順は追加しない。下の番号は参照用であり、Worksetや実装タスクではない。

## 実現したいこと

| 番号 | 実現したいこと | 必要な理由 | 確認する結果の案 | 整理状態 |

| 04 | プロジェクトを作成・保存・再読込する | 作業を中断し、継続できるようにする | 保存後に同じ構成を開き直せる | 初回候補 |
| 05 | 複数のフォームを作成・切替・名称変更する | 複数画面のアプリを作る | 対応する画面とソースを辿れる | 初回候補 |

部品の初回候補はラベル、入力欄、複数行入力、ボタン、チェック、選択欄、一覧表。部品ごとの詳細な振舞い、イベント種類、画面間の値渡しはUI・機能の工程で具体化する。
コピー・整列・削除、Undo／Redo、コード編集の操作も初期範囲案から引き継ぎ、詳細を後工程で定義する。

## 依存と未決定事項

| 論点 | 関係する要求 | 残っていること |
|---|---|---|
| 対応環境 | 03・13・14・16 | macOS最低版、CPU構成、ブラウザ、配布バイナリの版 |
| 実行ファイル | 09〜14・16 | 要求者側で用意する前提。版・場所・設定との対応 |
| 保存と再編集 | 02・04〜08・15 | 対応するソース規約、外部変更、複数ファイル保存失敗、手書き保護 |
| 実行の管理方式 | 13・14 | 既存機能＋macOS側処理で起動・所有追跡・停止・ログが成立するか |
| 追加実行ファイル | 03・13・14 | 専用管理サービスは未採用。既存機能の成立条件を踏まえて比較 |
| DBの詳細 | 10〜12 | 確認済みのSQLite既定・両DB基本CRUDを検証するSQL・データと実行ファイルの版 |
| コードと配置 | 06〜10・15 | JavaScript案、固定座標／追従配置、対応外ソースの扱い |
| 提供条件 | 全体 | 期限、予算、ライセンス、最終受入条件 |
| 正式要件の管理 | 全体 | 初回開発中の正式要件保管先・ブランチと正式版切替の対応 |

技術選択の工程は着手済みで未決定事項を残す。その決定が済んだと装わず、影響先を本表で追跡する。
個別アプリで使う全製品の常時必須化や、IDEの管理データをDBへ保存する要件は追加していない。

## 後続へ回す検討の軸

| 内容 | 初回候補との境界 |
|---|---|
| VB言語・既存VB6・COM／ActiveX互換 | VB6風の操作体験と区別する |
| 高度なブレークポイントデバッガ | 初回候補はログ・エラーを使った確認 |
| 任意ソースの完全逆変換 | 初回は対応範囲を定めた再編集を検討 |
| 独自部品の配布・拡張機構 | 初回の基本部品と区別する |
| 同時編集・組織権限管理 | macOSでのローカル利用を基本とする |
| 本番自動配備・クラウド運用 | 開発時の実行確認と区別する |
| 外部DB向け専用支援 | リモート利用はNyanQL群側で扱い、IDEの初回専用支援は追加しない |

## 重複・矛盾・代替案の整理

「ブラウザで開発する」と「ローカル利用」は両立する。保存・実行を支える機能はローカル側に必要となる。
「ソースを編集する」と「ポトペタへ戻る」は、対応範囲・手書き保護・競合処理を定義することで両立を検討する。
「追加バイナリを前提にしない」と「IDEから実行・停止する」は、技術実証が必要な組合せ。成立しない場合は影響と代替案を人間へ提示する。
NyanPUIとNyanQLの保存関数は引数形式が違うため、同じAPIとして扱わない。
