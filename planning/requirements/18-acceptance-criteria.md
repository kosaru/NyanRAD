# NyanRAD 初期版の受入条件案

## 初回DB範囲の人間判断

要求者は「SQLiteを既定にし、SQLite・DuckDBの両方で基本CRUDを確認し、直接接続とNyan8経由を対象にする」案に対し、「はい。それで進めましょう。」と回答した。
初回はB案を採用し、SQLiteを既定とする。SQLite・DuckDBそれぞれで登録・参照・更新・削除を、直接接続とNyan8経由の両経路で確認する。
同じSQL本文の互換保証、DB間変換、DB自動初期化・移行、IDE管理情報のDB必須保存は追加しない。
この判断は初回DB対応範囲であり、受入条件案全体・動作検証成功・正式Releaseの承認ではない。

この確認節は同じDB範囲を未決定とする以前の記述に優先する。


## 位置づけ

これまでの目的・初回範囲と了承された操作方針を、確認できる結果へ対応づける案。
新たな機能・技術リスクの受入・正式Releaseを承認する文書ではない。DB範囲はB案として人間確認済み。受入条件全体の正式判断は別途必要。

| 確認場面 | 受け入れるために確認する結果 |
|---|---|
| 構築物 | NyanRADがHTML・CSS・JavaScriptと提供されたNyanQL群実行ファイルで構成され、未採用の専用バイナリを必須にしていない |
| プロジェクト | 新規作成・保存・再読込ができ、製品別のソース・設定と対応する |
| 画面編集 | 初回対象の部品を配置・移動・サイズ変更し、プロパティを保存・再編集できる |
| コード編集 | 対象・イベントから処理を開き、通常JavaScriptの手書き本文を保持できる |
| サーバー処理・SQL | Nyan8の処理、NyanQLのSQL・設定を編集し、対象の実行結果を確認できる |
| 接続 | 直接とNyan8経由の両構成でJSONデータを受け渡せる |
| DB | 人間が選んだ初回範囲で基本CRUDと接続・SQL失敗を確認できる |
| 再編集 | 対応表現は取り込め、非対応部分は保持して制限を説明する。解析失敗で空のソース等に置換しない |
| コピー・名前変更 | 了承された手書き本文保持と参照更新範囲を守り、処理を意図せず複製・文字列置換しない |
| Undo／Redo | 対象操作を戻し・再適用でき、保存後に戻した内容は未保存と表示する |
| 未保存実行 | 保存して実行／保存済み内容で実行／中止が選択した通りに動く |
| 未保存切替 | 保存／破棄／中止が選択した通りに動き、失敗を成功扱いしない |
| 競合・保存失敗 | 差分と失敗対象を示し、自動上書きしない。一部保存状態で新たに起動しない |
| 起動・再実行 | 設定に対応する対象を起動し、二重起動を避け停止後に再実行する |
| 一部起動失敗 | 全体成功とせず、今回起動した対象だけを停止する。停止失敗も表示する |
| 停止・不明状態 | 管理対象以外を止めず、失敗・不明と停止済みを区別する。無条件の強制終了をしない |
| ログ | 対象に対応する取得可能なログ・エラーを確認できる |
| IDE外利用 | 通常ソースを対応するNyanQL群で実行でき、NyanRAD起動を必須としない |

## 確認例の組合せ

macOSローカルで、フォーム・基本部品・イベント・サーバー処理・DB操作を含む小さな検証アプリを作る。
同じ検証アプリの構成を変えて、直接接続とNyan8経由を確認する。
SQLite・DuckDBの両方で検証する。
同じSQLや同じDBファイルを両DBで共用する要件は追加しない。

## 判断前に必要な証拠

対象の要件Commitと実装・テスト対象Commit、実行ファイルの版、確認したmacOS・CPU・ブラウザ、テスト結果、生成ソース、主要な失敗例、未解決事項を対応づける。
具体的なテスト設計・証拠作成は正式入力成立後に行う。
未実証の実行管理、未確定のDB範囲、対応環境、提供条件は、成功実績や受入済み制限と扱わない。
性能値、対象外のVB互換・高度デバッガ等の達成条件を追加しない。

## 技術的完了と正式な受入

初回範囲の技術確認ができても、人間による正式な受入・Release判断は別に記録する。
人間が選んだ正確な対象Commitと、同じ内容の確認資料を基に判断する。
