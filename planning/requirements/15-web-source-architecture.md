# NyanRAD HTML・CSS・JavaScriptによる構成案

## 構築言語の前提の再確認

要求者は「HTML＋CSS＋Javascriptで作るんだよね？」と確認し、「その前提を外してなければいい。次進めよう。」と指示した。
NyanRADの画面と管理処理はHTML・CSS・JavaScriptで構築する。OS側の能力は要求者が用意するNyanQL群の実行ファイルを通して使う。
新しいGo等の専用管理バイナリや、OS別の外部スクリプトを必須とする構成を採用済みとはしない。
既存機能で満たせない条件が見つかった場合は、その不足を提示する。前提を変えた案へ独断で切り替えない。


## 使用する場所

| 場所 | 記述するもの | 担うこと |
|---|---|---|
| ブラウザ | HTML・CSS・JavaScript | デザイナー、プロパティ、コード編集、プレビュー、管理APIの呼出 |
| NyanPUI上 | JavaScript・既存のJSON設定 | IDE画面配信、プロジェクト読込、保存・削除等の管理API候補 |
| 必要に応じたNyan8・NyanQL上 | JavaScript・SQL・既存JSON設定 | 生成アプリのサーバー処理・DB処理。IDE自身の管理DBを必須としない |

SQLとJSONはNyanQL群の既存ソース・設定として使用する。NyanRADの実装言語を別のネイティブ言語へ変える意味ではない。
NyanRADを動かすサービスと、生成アプリのサービスは設定・保存場所・起動対象を区別する。

## 読込・保存の流れ

```mermaid
flowchart LR
 B["ブラウザの編集画面"] -->|"対象と変更内容"| J["NyanPUIの管理用JavaScript"]
 J -->|"既存の読込・保存関数"| F[("プロジェクトの通常ファイル")]
 F -->|"読込結果"| J
 J -->|"保存結果・差分・エラー"| B
```

既存調査で確認したNyanPUIのnyanGetFile、nyanSaveFile、nyanDeleteFileを利用する案。
保存先と対象プロジェクトの対応、差分確認、手書き保護、対象別の保存結果は管理用JavaScript側で扱う。
ソース本文を保存するためにシェルコマンドへ本文を埋め込む方式は第一案にしない。
複数ファイルの途中失敗、外部編集との競合、一覧・名称変更等の必要機能は別途成立確認が必要。

## 実行・停止の流れと残る不足

ブラウザから実行対象を指定し、管理用JavaScriptが既存のホストコマンド機能等で起動・状態確認・停止を依頼する案。
既存のnyanHostExecは終了を待つため、常駐サーバーをそのまま同期呼出しして完了する機能ではない。
次の条件はJavaScriptを記述するだけで成立済みとは扱わない。

- 起動後に管理APIが応答できること。
- 管理する実行対象を識別し、別サービスを止めないこと。
- 標準出力等の扱いを含め、コマンド完了待ちが残らないこと。
- 起動失敗・停止失敗・状態不明を区別できること。
- ログを対応する実行対象から取得できること。
- IDEの再読込・再起動後に管理対象をどう扱うか定まること。

OSの既存コマンドを使う可能性と、新規の外部スクリプトを配布することは区別する。具体的なコマンド構成や追加依存は未決定。
既存機能で不足があれば、フレームワークに必要な能力と影響を調査資料として返す。フレームワーク本体を変更する作業や、専用サービスを追加する作業は今回開始しない。

## 今回の工程で進めること

1. 管理機能を「読込・保存」「実行対象の把握」「起動・停止」「ログ取得」に分け、既存能力との不足を追跡する。
2. 動作とデータの未決定事項を解消し、検証すべき条件を要件資料にそろえる。
3. 正式入力が成立した後、対応する実行ファイルで技術実証する。

CPU・OS版・ブラウザ版の細目は最終的な提供・検証条件として残すが、構築言語の前提を確認するための先行条件にはしない。
この資料は構成案と不足の整理であり、保存・実行管理の動作保証や実装完了の報告ではない。
