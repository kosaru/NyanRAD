# NyanRAD 編集操作の細目案

初回デザイナーの方針を受けた詳細提案。以下の細目は未承認であり、実装契約ではない。

| 操作 | 提案する動作 | 理由・残る確認 |
|---|---|---|
| 部品コピー | 新しい名前で配置を複製し、元の手書き処理本文は自動複製しない。イベント処理があることを示す | 同名衝突と処理の意図しない重複を避ける。処理共有の操作は別途検討 |
| 部品名の変更 | IDEが管理する識別・CSS・結線の対応を更新し、手書き本文の参照は影響を示して残す | 任意コードを文字列置換で壊さない。追跡できない参照を保証しない |
| Undo／Redo | 部品の追加・削除・移動・寸法・プロパティ・整列・名称変更を対象とする | コード編集の履歴はエディター側と分ける案。横断履歴は初回へ追加しない |
| 保存と履歴 | 同じ編集セッションの保存では履歴を保つ。再読込・プロジェクト切替で区切る案 | 保存の取り消しでファイルを自動巻戻しせず、戻した編集内容を未保存とする |
| 部品削除のUndo | 部品とIDE管理の結線を戻す。手書き本文は削除時にも残っている前提 | 手書き本文を二重に生成しない |
| イベント引数 | 対象、現在値、ブラウザイベント等を、実行場所に合った明示的な引数として渡す案 | 独自のVB互換オブジェクトを暗黙導入しない。署名と値型は機能仕様で定める |
| フォームLoad | 対象DOMとIDE管理のイベント結線が利用可能となった後に一度呼ぶ案 | 全画像読込完了や任意の非同期初期化完了とは別 |
| 一覧の行選択 | 行を識別できる値と、その時点の行データを処理へ渡す案 | 行キーの指定・重複・データ更新後の選択保持を定義する必要がある |
| 配置値 | フォーム内の座標と寸法を数値で編集し、表示とソースを対応づける | 単位・小数・最小寸法・フォーム外配置の規則は未決定 |
| 解析できない表現 | 対象を保持し、編集制限の理由とコードの場所を示す | 関係のない部品まで一律編集禁止にしない案 |

## 対応関係の確認例

部品を削除 → 手書き本文は残る → Undoで部品と結線が戻る → 再生成で本文を複製しない。
部品名を変更 → 管理対象だけ更新 → 既存本文の参照へ注意を示す → 開発者が本文を修正する。
保存 → 配置をUndo → 画面は戻るがファイルは直前の保存内容のまま → 未保存を表示 → 保存すると戻した内容を反映する。

## 残る提供条件

macOS最低版・CPU・ブラウザ、配布実行ファイルの版、DB範囲、実行管理の成立確認、ライセンス・期限・予算・受入条件は別の未決定事項として残る。
細目の採用後はUI・機能・データ・接続図へ同期する。
