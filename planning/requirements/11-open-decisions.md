# NyanRAD 要件確定までの判断・解消一覧

## 最初に確認する操作方針の提案

以下は今回整理した提案。人間が採用済みとは扱わない。

| 論点 | 提案 | 影響 |
|---|---|---|
| 未保存で実行 | 保存して実行／保存済み内容で実行／中止を選べるようにする | 編集内容と実行内容を区別する必要がある |
| 未保存で切替・再読込 | 保存／破棄／中止を選ぶ。保存失敗なら切替を完了しない | 意図しない破棄を防ぐ |
| 一部ファイルの保存失敗 | 解消するまで新たな実行を止め、対象別の結果を残す | 混在した状態を実行しない。既存の実行対象の扱いは別に定義 |
| 外部変更との競合 | 差分を示し、再読込／編集内容を保存／中止を選ぶ案 | 上書き・破棄する対象の明示が必要 |
| 部品削除 | 部品と管理するイベント結線を対象にし、手書き処理本文は残す案 | 未使用コードが残り得る。参照検出の限界を示す |
| 状態不明・停止失敗 | 不明・失敗を表示し、無条件の強制終了はしない | 再接続・手動確認の導線を別途定義 |

要求者が選んだ後、UI・機能・データ・図へ同じ意味を反映する。

## 後続の解消事項

| 事項 | 進め方 |
|---|---|
| 配置・部品・イベント・再編集範囲 | AIが比較案を作り、要求者が意味と範囲を判断 |
| macOS最低版・CPU・ブラウザ | AIが制約を整理し、提供範囲を要求者が選ぶ |
| 実行ファイルの版・配置 | 用意される版を確認し、現行ソースとの差を調査 |
| DBの既定値と対応範囲 | SQLite・DuckDBについて初回範囲の判断材料を用意 |
| 保存・起動・停止の技術成立 | 未実証を明示。実装・実証は正式な入力成立後。追加実行ファイルは未採用 |
| 期限・予算・ライセンス・受入条件 | 提供上の判断は要求者が行う |
| 正式要件の初回保管とブランチ | 正本と初回リポジトリ運用の明示指示を踏まえた対応案を整理 |

## 正式な引渡しの前に

判断を反映した人間向け資料と固定Snapshot、同じ意味のAI構造化成果物・対応表、IFDAMの形式検証を用意する。
Candidate境界、承認Commit、正式要件の反映、Baseline成立、引渡し可否、Work Requestは正本の順序で成立させる。
現状は初稿と整合確認の段階。未決定をAIの既定値で埋めて実装へ渡さない。
