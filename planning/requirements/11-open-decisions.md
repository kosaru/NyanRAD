## 今回確認された操作方針

要求者は次の５項目への確認に「はい。これで良いので進めてください。」と回答した。

1. 未保存で実行するときは「保存して実行」「保存済み内容で実行」「中止」を選ぶ。
2. 未保存でプロジェクト切替・再読込するときは「保存」「破棄」「中止」を選ぶ。
3. 保存競合は差分を示し、自動上書きしない。
4. 部品を削除しても手書き処理の本文は残す。
5. 保存失敗・停止失敗を成功扱いにせず、確認できる状態を示す。

この節は本文の同じ論点について「案」「未決定」とした以前の記述を更新する。未確認の詳細条件まで承認した意味ではない。
部分保存後の実行禁止、競合画面の具体的な選択肢、強制停止の提供条件、名称変更の自動修正範囲は今回の５項目に含めず、検討を続ける。


| 論点 | 提案 | 影響 |
|---|---|---|
| 未保存で実行 | 保存して実行／保存済み内容で実行／中止を選べるようにする | 編集内容と実行内容を区別する必要がある |
| 未保存で切替・再読込 | 保存／破棄／中止を選ぶ。保存失敗なら切替を完了しない | 意図しない破棄を防ぐ |
| 一部ファイルの保存失敗 | 解消するまで新たな実行を止め、対象別の結果を残す | 混在した状態を実行しない。既存の実行対象の扱いは別に定義 |
| 外部変更との競合 | 差分を示し、再読込／編集内容を保存／中止を選ぶ案 | 上書き・破棄する対象の明示が必要 |
| 部品削除 | 部品と管理するイベント結線を対象にし、手書き処理本文は残す案 | 未使用コードが残り得る。参照検出の限界を示す |
| 状態不明・停止失敗 | 不明・失敗を表示し、無条件の強制終了はしない | 再接続・手動確認の導線を別途定義 |

上の５項目はUI・機能・データ・接続図へ同期済み。部分保存、競合画面の具体操作、名称変更・Undo等の詳細は次に検討する。
