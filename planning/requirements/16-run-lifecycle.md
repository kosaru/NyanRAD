# NyanRAD 実行・停止・ログの動作案

## 実行・停止の追加方針の確認

要求者は次の５項目に対し「はい。いいですよ。」と了承した。

1. 一部だけ保存できた状態では、新たな実行を止める。
2. 二重起動を避け、停止してから再実行する。
3. 起動に一部失敗したら、今回起動した対象だけを停止する。
4. タブを閉じただけでは自動停止を保証しない。
5. 状態不明のプロセスを自動で強制終了しない。

この節は同じ論点を以前「提案」「未決定」とした記述に優先する。
今回起動した対象の停止に失敗した場合も成功扱いせず、確認できる状態を表示する。既存の外部サービスは停止対象に含めない。
HTML・CSS・JavaScriptと要求者提供のNyanQL群実行ファイルの前提を維持する。実行管理の技術成立・動作実証、追加実行ファイルの採用、正式Baseline・実装開始は今回の了承に含めない。



## 前提と未実証の境界

NyanRADはHTML・CSS・JavaScriptで作り、要求者提供のNyanQL群実行ファイルを利用する。初回はmacOSローカル。
管理用JavaScriptから既存機能を使う方針を維持する。本書は利用者へ必要な結果を具体化する案であり、常駐プロセス管理が実装済み・動作確認済みという意味ではない。

## 実行対象の選び方

プロジェクトで使用するNyanPUI・Nyan8・NyanQLと、それぞれの設定・実行ファイルを対応づける。
全製品の常時起動を必須としない。既に外部で起動しているサービスを、自動的にIDE所有として扱わない。
初回の案は「プロジェクト単位で一組の実行を管理する」。同じプロジェクトの複数構成を並列実行する機能は別途採用判断とする。

## 実行ボタンから結果確認まで

1. 実行対象、設定、保存結果を確認する。
2. 未保存なら了承済みの「保存して実行／保存済み内容で実行／中止」を示す。
3. 一部保存に失敗して内容が混在する場合は、解消まで新たな実行を止める案。
4. 起動を依頼し、使用する保存内容と対象サービスの状態を対応づける。
5. 起動が確認できたサービスと失敗・不明のサービスを分けて表示する。
6. 対象画面のプレビューとログ確認へ進む。

実行済みの場合は二重起動せず、現在の実行内容を表示して「停止して再実行」へ進む案。
自動ホットリロードだけで、画面・処理・設定の全変更が反映されたと扱わない。
サービスの起動順・起動確認方法・待ち時間は具体的な実行ファイルの版を踏まえて検証する。

## 一部だけ起動できた場合

対象サービスごとに結果を示し、全体を成功扱いにしない。
今回起動できたサービスを停止してから再試行する案を第一候補にする。
停止できない対象は失敗・不明として残し、勝手に別サービスや同じポートのプロセスを終了しない。
起動前から存在する外部サービスは停止対象に含めない。
この回復動作は追加の提案であり、要求者確認前に採用済みとしない。

## 停止と状態確認

停止は管理対象の識別ができるサービスだけへ要求する。
「停止要求を送れた」と「実際の終了を確認できた」は別の結果として扱う。
止まらない場合は対象と確認できる状態を表示する。無条件の強制終了はしない案。
ブラウザタブを閉じただけで必ず全サービスが停止するとは保証しない。タブ終了での自動停止は初回要件へ追加しない案。

IDEの再読込後は管理対象の記録と実際の状態を照合してから操作可能とする案。
PIDだけを根拠に所有を復元しない。再確認できない対象は「不明」と表示し、自動で停止・再起動しない。
具体的な識別・照合方法、管理情報の保持方式は技術課題として残す。

## ログの表示案

ログはプロジェクトとサービスを選んで確認できるようにする。
起動・停止の結果と、生成アプリの処理ログを区別する。
取得できない時刻・ファイル位置等を推測で補わず、取得失敗・文字コード・ローテーション等の扱いを定める。
既存ファイルを毎回削除してから起動する案にはしない。ログの永続履歴管理・検索分析は初回に追加しない。
保持上限や表示件数等の値は未決定。通常ソースを持ち出すときにIDEの管理ログまで必須にしない。

## 必要な情報と既存機能の不足

| 結果 | 必要な情報 | 調査・検証すること |
|---|---|---|
| 対象の起動 | 実行ファイル、設定、作業場所、保存内容との対応 | ホストコマンド終了待ちを残さず常駐起動できるか |
| 対象の識別 | プロジェクト・サービスと実プロセスの対応 | PID再利用・IDE再読込を含む所有確認 |
| 停止完了の表示 | 停止要求と実際の終了結果 | 別サービスを止めず終了を確認できるか |
| 失敗からの回復 | 今回起動した対象と既存の対象の区別 | 一部起動失敗時の停止・再試行が成立するか |
| ログ確認 | 取得元、対象サービス、取得位置 | 既存ログとAPIで必要な内容を取得できるか |

追加実行ファイルやOS別外部スクリプトの必須化を、これらの不足へ自動的に当てはめない。
既存能力で満たせない場合は、満たせない条件と選択肢を要求者へ返す。正式な入力成立前に実装を開始しない。

## 確認したい追加方針

- 部分保存で混在しているときは、新たな実行を止める。
- 同じプロジェクトの二重起動を避け、停止してから再実行する。
- 一部起動失敗では今回起動した対象だけを停止して再試行する。
- タブを閉じたことだけで自動停止を保証せず、IDEの停止操作を用意する。
- 状態が確認できない対象へ自動停止・再起動・強制終了をしない。

上記５項目は要求者了承済み。UI・機能・データ・接続図へ同期した。
