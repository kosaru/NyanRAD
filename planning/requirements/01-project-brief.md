# NyanRAD 企画確認書（初稿）

## 背景と目的

NyanQL群でアプリを作る開発者が、ファイルを個別に編集する手間を減らし、画面作成から実行まで一つの環境で進められるようにする。
ブラウザ上でVB6のように部品を配置して画面を作り、イベントやサーバー処理、SQLを編集できる環境を目指す。

生成物は編集可能なソースコードとし、NyanQLフレームワーク群の体裁を保つ。特定の業務アプリや初心者向けへの限定はしない。
この目的と対象者・困り事・改善方向は、要求者との対話で確認済みである。

## 対象者と狙う成果

対象者はNyanQL群でアプリを開発する人。
画面を配置し、処理を書き、DBへ接続し、実行して結果を確認し、保存して開き直す流れを一つの環境で進められることを狙う。
時間短縮率などの数値目標は未設定であり、AIから数値を補わない。

## 初期範囲の検討方針

以下は要求者が検討の軸として了承した区分。詳細な機能や受入条件は後の工程で具体化する。

| 初回の軸 | 内容 |
|---|---|
| プロジェクトと画面 | 新規作成・保存・再読込、複数フォーム、部品配置とプロパティ編集 |
| 処理の編集 | 画面イベント、Nyan8のサーバー処理、NyanQLのSQLと設定 |
| 接続と実行 | NyanPUIからNyanQLへの直接接続とNyan8経由、プレビュー・停止・ログ確認 |
| 編集の継続 | 配置のやり直し、手書き処理を保つ保存・再編集、通常ソースとしての利用 |

初回から後続へ回す検討の軸は、VB言語互換・既存VB6取込・COM／ActiveX互換、高度なデバッガ、任意ソースの完全逆変換、独自部品の拡張機構、同時編集、本番自動配備、外部DB専用支援である。

## 既知の前提と制約

NyanPUI・Nyan8・NyanQLを対象とする。個別アプリの構成に応じて使用する製品を選ぶ。
実行ファイルは要求者側で用意する。初回はSQLiteを既定とし、SQLite・DuckDBそれぞれで基本CRUDを直接接続・Nyan8経由の両経路で確認する。
NyanRADのブラウザ画面をHTML・CSS・JavaScriptで構築する案は、保存や実行を担うサーバー側機能と併せて検討する。

## 成果を確認する観点

画面作成から処理編集・接続・実行・保存・再編集までの一巡ができるかを確認する。
保存したソースがNyanQL群の構成に沿い、通常の実行環境で利用できるかを確認する。
手編集した処理を保持しながら画面編集を継続できる範囲と制限を明らかにする。
これらは企画段階の観点であり、具体的な受入条件は後の工程で定める。

## 関係者と判断主体

要求者が目的・範囲・要件内容・提供条件の判断を担う。
AIが資料作成、調査、未決定事項の整理、GitHubの進捗記録を進める。
実装は正式な要件と作業指示が成立した後に進める。

## 未決定事項

| 論点 | 今後確認する内容 |
|---|---|
| 利用環境 | macOSローカル利用。保存先、実行設定、最低OS版・CPU・ブラウザの検証範囲 |
| 提供条件 | 期限、予算、ライセンス、最終的な受入条件 |
| 技術条件 | 対応する実行ファイルの版、コード言語、配置方式、再編集の保証範囲 |
| DB | 検証用データ・SQLと採用実行ファイルの版（初回DB範囲は確認済み） |
| 正式要件の管理 | 初回の正式要件保管先とブランチ、正式版への切替記録 |

期限・予算などの未決定事項は未決定のまま表示し、影響が具体化した時点で判断材料を提示する。
