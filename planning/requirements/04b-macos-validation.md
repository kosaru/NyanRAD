# macOSでの保存・実行管理：検証条件案

## 決まった利用条件

要求者の指示：「一旦macOSで作ってみよう。」
初回はmacOSでのローカル利用を対象として要件定義を進める。Windows・Linuxの初回対応を含む判断ではない。
リモートサービスの利用はNyanQL群側で扱う方針を維持する。専用管理サービスの追加は未採用。

macOSの最低バージョン、Apple Silicon／Intelの対応範囲、ブラウザ、配布バイナリの版は未決定。現在作業中のPCの構成をそのまま対応要件にしない。

## 既存基盤を使う技術案

NyanPUIでIDE画面と管理APIを配信し、サーバーJavaScriptから既存の読込・保存・削除を使う案を優先して調べる。
起動・停止は、ホストコマンド機能とmacOS側の操作を組み合わせる候補。具体的なプロセス管理方式は未決定。
シェルへ常駐サーバーを同期実行するだけではAPIが終了を待つため、起動後の応答、プロセス所有の追跡、出力先の扱いを別に定義する。

## 確認すべき利用上の結果

| 場面 | 確認したい結果 |
|---|---|
| 初回起動 | 用意された実行ファイル・設定の場所を把握でき、不足や起動失敗が分かる |
| 保存 | 日本語・空白・引用符等を含む本文やパスを壊さず保存できる |
| 保存失敗 | 失敗を表示し、保存済みと誤認させず、未保存編集を保持する |
| 外部編集 | 読込後に外部で変更されたソースを無条件に上書きしない |
| 複数ファイルの変更 | 保存が途中で失敗したときに、反映状態と実行可否を説明できる |
| アプリ実行 | 対象プロジェクトの設定とソースを使い、起動できたかを確認できる |
| 二重実行・ポート競合 | 実行済みや競合を区別し、別プロジェクトへ誤接続しない |
| 停止 | IDEが管理する実行対象だけを停止し、他のサービスを止めない |
| 異常終了 | 終了したこととエラーを確認でき、再実行へ進める |
| IDEの再読込・再起動 | 実行中プロセスを見失った場合の表示・再接続・停止方針が明確 |
| ログ | 実行対象に対応するログを表示し、文字コードやローテーションを扱える |
| アプリの持出し | 保存した通常ソースをNyanRAD外でも対応するNyanQL群で起動できる |

これは要件定義用の検証条件案。詳細なテスト手順・合格基準は機能を具体化した後に固定する。

## 専用管理サービスの必要性を判断する基準

既存機能とmacOS側処理で、起動した対象の識別・停止・ログ取得・失敗時の扱いが成立するかを確認する。
成立する場合は、追加実行ファイルを前提としない案を継続する。
成立しない場合は、どの条件が満たせないかと影響を提示し、方式の変更や専用管理サービスの追加を比較する。
単にホストコマンドが使えることだけでは、管理機能が完成しているとは評価しない。
